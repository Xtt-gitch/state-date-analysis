# Concept Learning Material（概念学习资料生成）

## Overview

为**任意新概念**（任意领域、任意难度）生成一份结构化概念学习资料，帮助用户从"听说过"进阶到"能用自己的话讲清楚、知道何时用、知道边界在哪"。核心价值：① 用大白话与类比做**个人解释**；② 讲透**核心机制**而非停留在定义；③ 用真实例子支撑**应用场景**；④ 通过**边界辨析**消灭似是而非的混淆；⑤ 每一条关键论断都有可核实的**来源链接**。

概念可以是用户明确给出的术语（如"协方差""贝叶斯定理""工厂模式""机会成本"），也可以是一个现象、方法或理论名称。本技能不要求预先具备该概念的专门知识——不知道或不确定时必须先检索核实，禁止仅凭记忆生成。

## 适用场景（When to Use）

在以下情形触发本技能：

- 用户要求"学习 / 搞懂 / 学透 / 讲清楚 / 深入理解"某个概念，且期望系统性材料而非一句话解释。
- 用户要求生成"概念学习资料 / 讲义 / 学习笔记 / 复习材料 / 科普讲解"。
- 用户为考试、备课、自学做准备，需要一份结构完整的知识点材料。
- 用户要求解释某个概念"是怎么工作的 / 内部机制 / 本质"，尤其是专业术语。
- 触发示例："帮我学习条件概率"、"写一份『注意力机制』的学习资料"、"彻底搞懂什么是梯度下降"、"复习一下机会成本"。

**不适用**：仅需简短定义或词典式查询；与概念学习无关的文件处理、写作等任务。简短问答时按普通对话回答即可，不必套用本流程。

## 输入信息（Input）

本技能**最少只需一个输入：概念名称**，其余信息缺省时可合理推断或采用默认值，不得因信息不全而卡住。可以主动收集的增强输入：

| 信息 | 是否必需 | 说明与默认 |
|---|---|---|
| 概念名称 | ✅ 必需 | 术语的规范名称。若用户表述模糊（口语、缩写、指代不清），先澄清或给出最可能的规范名并在文中注明别名。 |
| 学科/领域 | 可选 | 无法从概念名推断时询问；多义词（如同一词在统计与编程中含义不同）必须确定语境。 |
| 学习者水平 | 可选 | 新手 / 进阶 / 复习。默认：新手友好，术语首次出现必解释。 |
| 学习目的 | 可选 | 考试、应用、备课、科普。影响例子选取与详略。 |
| 输出语言 | 可选 | 默认与用户语言一致；术语保留中英双语。 |
| 输出形式 | 可选 | 默认在对话中输出完整 Markdown；用户要求时可保存为文件（如 .md/.docx）。 |
| 期望详略/篇幅 | 可选 | 默认中等篇幅（讲透一个概念）；无硬性页数限制。 |

处理原则：**任意新概念均可作为输入**，包括超出训练知识或发布时间较新的概念——此时"检索核实"步骤为强制项而非可选项。

## 生成步骤（Generation Steps）

1. **解析概念并消歧**：提取概念名称，判断学科语境；如为多义词或表述不清，简要确认；记录概念的规范中英文名及别名。
2. **检索与核实（强制）**：用 WebSearch 检索权威来源，覆盖：权威定义、官方文档/规范、教材或课程讲义、维基/百科、知名机构或论文。对核心定义至少获得 2 个独立来源的交叉印证；注意区分该概念的通用含义与特定领域含义。新概念、冷门术语、含具体数字/公式/历史背景的内容尤其必须检索。
3. **构建个人理解**：在核实基础上提炼——这个概念的**本质是什么**、**内部如何运作**、**关键要素/公式/流程**、**一个能抓住直觉的例子或类比**、**它解决了什么本来存在的问题**。
4. **识别易混淆点**：找出与之相近/易混的概念（用于边界辨析），以及初学者常见误区。
5. **按输出结构成稿**：严格按下方"输出结构"组织内容，撰写每一部分；例子必须具体、真实、可理解，禁止空话套话。
6. **自检与修订**：对照"自检要求"逐条检查并修订；发现来源不足或断言无法回溯时，回到步骤 2 补充检索。
7. **交付**：默认在回复中直接输出完整资料；如需文档，另存为文件交付。

## 输出结构（Output Structure）

输出以概念名为标题（含中英双语与学科标注），随后**按顺序**包含以下五大部分。结构固定，任何一次生成都不得省略其中任何一部分：

### 1. 个人解释（Personal Explanation）
- 用"给上一课的自己"讲的大白话复述概念，配 1 个直观类比或生活化例子。
- 体现"这个概念本质上是……"，解释它为什么被发明/提出（解决什么问题）。
- 语言适配学习者水平；只在此处允许适度口语化，关键术语仍须准确。

### 2. 核心机制（Core Mechanism）
- 严谨定义 + 内在原理：分步、分点讲清概念**如何运作**，而非停留在字面定义。
- 列出关键要素、前提条件、公式/伪代码/流程图（如适用）；复杂机制配 ASCII 示意图或步骤编号。
- 覆盖"常见但关键的细节"（如公式中每个符号的含义、流程中容易忽略的环节）。

### 3. 应用场景（Application Scenarios）
- ≥2–3 个真实、具体的场景，覆盖不同领域或层次（至少一个贴近用户学习目的）。
- 每个场景写明：**何时用、为什么用、怎么用**，最好带具体数据/上下文小例子。
- 如果概念在某个知名领域是标配（如梯度下降之于机器学习），必须点出。

### 4. 边界辨析（Boundary & Discrimination）
- 与 ≥1 组相近概念做对比（可用小表格：概念 / 相同点 / 关键区别 / 典型场景）。
- 明确适用边界：前提假设、失效条件、适用范围与不适用的情形（含反例）。
- 列出 ≥2 条初学者常见误区或"最容易想当然的地方"并纠正。
- 若概念本身存在争议、不同学派定义不同或信息已过时，如实说明分歧。

### 5. 来源链接（Source Links）
- 以列表形式给出生成时所依据的来源：`标题 — 类型（官方文档/维基/教材/论文/课程…）— URL`。
- 每条来源标注其支撑的内容点（如"定义依据""公式出处""应用案例"）。
- 链接必须真实可访问（见"资料来源要求"）。

> 可选扩展（非必需，仅在明显有助于学习时添加，避免臃肿）：`速记卡（一页要点）`、`自测题 3–5 道`、`延伸学习路径`。

## 资料来源要求（Source Requirements）

- **权威优先**：按优先级选择来源——官方文档/规范、正式教材与课程讲义、维基百科/权威百科、同行评审论文、知名机构/从业者权威文章；个人博客、问答帖仅作补充线索，不作主要依据。
- **交叉验证**：核心定义、关键机制至少经 2 个独立来源印证；存在分歧时并列呈现而非只取其一。
- **可追溯**：涉及事实、数字、公式、历史、版本等硬信息时必须能回溯到具体来源；**严禁编造来源或链接**。
- **真实性核查**：列出的每条 URL 必须是检索中真实出现、可访问的地址；无法验证的内容明确标注"⚠️ 待核实"，不得伪装为事实。
- **知识边界**：若该概念超出自身可靠知识范围（新发布、冷门、或高度事实性），必须先行检索；检索仍无法确认时如实告知用户，并给出最接近的可信信息与不确定性说明。
- **语言与命名**：概念保留中英规范名，注明学科归属；引用的定义注明出处而非默认为通用共识。

## 自检要求（Self-Check Before Delivery）

交付前逐条检查，发现问题立即修订，不得带着问题输出：

1. **准确性**：定义、机制、数字、公式与权威来源一致，无幻觉或编造；所有来源链接真实可访问。
2. **说人话**：个人解释是否真的通俗？类比是否准确、不产生误导？
3. **机制完整**：核心机制是否讲清"如何运作"，而非停留在定义？关键要素有无遗漏？
4. **例子具体**：应用场景 ≥2–3 个，具体、真实、可想象，没有泛泛而谈？
5. **边界到位**：至少 1 组相近概念对比、明确适用前提与失效情形、≥2 条常见误区纠正？
6. **来源充分**：核心论断均有来源支撑；来源清单完整标注类型与用途；无编造链接？
7. **适配水平**：术语首次出现有解释，内容详略与学习者水平、学习目的一致？
8. **消歧完成**：多义词已按语境定位；使用了规范概念名（含别名说明）？
9. **诚实边界**：存在争议、分歧或不确定性时已如实标注，未夸大确定性？

完成全部检查且通过后，才向用户交付学习资料。
