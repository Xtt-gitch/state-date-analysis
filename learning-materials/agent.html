CONCEPT LEARNING MATERIAL

Agent（AI 智能体 / 智能代理）

AI Agent = LLM（推理）+ 规划 + 记忆 + 工具使用 —— 让大模型从"回答问题"进化为"替你办成事"的系统。

学科：人工智能（LLM 应用 / Agentic AI） 难度：入门 → 进阶 别名：AI Agent / 智能体 / AI 代理 / agentic AI 检索核实：2026-09-08

1个人解释

给"上一课的自己"讲：把大语言模型（LLM）想象成一位博学但足不出户的专家——你问什么它答什么，但什么也做不了。Agent 就是给这位专家配上手（工具）、记事本（记忆）和做计划的头脑（规划），让他变成能出门跑腿、把事真正办成的"全能助理"。你只需说目标（"帮我订一趟下周去北京的行程"），剩下的查航班、比价格、订酒店、写行程单都由它自己一步步完成。

本质：Agent 是一个软件系统，它以 LLM 为"大脑"，在"感知 → 推理/规划 → 行动 → 观察结果 → 再推理"的循环中自主推进目标，而不是一问一答就结束。经典的定义强调四个字：自主性（Autonomy）——能在无人逐步干预的情况下决定"下一步做什么"。

为什么需要它：纯对话模型只能生成文本，而现实任务（查资料、算账、改代码、发文件、调 API…）是多步、需要与外部世界交互的。Agent 解决了"模型能力无法作用于真实环境"的问题。业界广泛引用的构成公式是：

AI Agent = 大语言模型 LLM（推理与决策"大脑"）
         + Planning  规划（把大任务拆成子任务、自我反思）
         + Memory    记忆（短期 = 当前上下文；长期 = 外部存储）
         + Tool Use  工具使用（搜索、API、代码执行、文件操作…）

类比提醒：LLM 本身是"被动应答的知识专家"；Agent 是"拥有专家大脑、还能动手办事的执行系统"。两者最大的差别不是"会不会回答"，而是能否在闭环里自主行动。

2核心机制

2.1 定义的来龙去脉

"智能体"一词在 AI 中历史悠久：经典教材（Russell & Norvig《人工智能：一种现代方法》）把智能体定义为"能通过传感器感知环境、通过执行器对环境施加影响的实体"，并以"理性地最大化目标达成度"来衡量智能程度；更早的 Wooldridge & Jennings（1995）则强调"处于环境中、能自主行动以实现设计目标"的计算机系统。今天的 AI Agent（agentic AI） 是这一思想在大模型时代的具体形态——把 LLM 当作感知与决策内核，再套上工具、记忆和编排层。不同来源对"什么是 Agent"表述各异、尚无唯一标准定义，但自主决策 + 闭环执行 + 工具使用是共识特征。

2.2 四大构成组件如何协作

组件角色比喻作用
LLM（大脑）专家本人理解指令、推理、做决策；决定下一步"想还是做"
规划 Planning做计划任务分解为子目标；自我批评/反思（Reflection）以纠错改进
记忆 Memory记事本短期记忆＝上下文窗口内的对话与工具结果；长期记忆＝向量库等外部存储，跨会话保留经验
工具 Tools双手把决策变成真实动作：调用 API、搜索、执行代码、读写文件，并把结果送回上下文

2.3 核心循环：ReAct（Reason + Act）

2022 年论文《ReAct: Synergizing Reasoning and Acting in Language Models》提出了现代 LLM Agent 最常见的主循环，让模型在推理与行动之间交替：

用户给出目标
   │
   ▼
Thought     思考：结合当前情况，决定下一步（"我需要查航班价格"）
   │
   ▼
Action      行动：调用某个工具 search("北京-上海 机票 2026-09-20")
   │
   ▼
Observation 观察：拿到工具返回的真实结果
   │
   ▼
（再次 Thought → Action → Observation…… 循环，直到信息足够）
   │
   ▼
Final Answer / 执行完毕
（工程上常设最大步数、超时、预算等终止条件防止死循环）

ReAct 的意义在于把"会想（Chain-of-Thought）"与"会做（工具调用）"结合：思考让行动有方向，行动让思考获得真实世界的反馈，从而减少凭空编造。原论文在 HotpotQA 等问答与 ALFWorld、WebShop 等决策任务上均超过纯推理或纯行动基线。

2.4 一个关键的架构区分：Workflow 与 Agent

Anthropic 的工程实践把"智能系统"分为两类：Workflow（工作流）是 LLM 与工具被预定义的代码路径编排；Agent 则是 LLM 自己动态决定流程与工具调用。后者适合步骤无法预判的开放式任务，但更慢、更贵、错误会累积——官方建议"先选最简单的方案，不是所有任务都该做成 Agent"。

补充：Agent 的"自主程度"是一条谱系而非二值开关——有的系统每个关键动作都需人工批准（Human-in-the-Loop），有的只在受限测试环境里全自主。"自主"必须说清楚：去掉了哪些人工环节、能碰哪些动作、在什么时限内。

3应用场景

3.1 软件工程：编码 Agent（已规模商用的头号场景）

何时用：面对真实代码库的 bug 修复、多文件改动、按 Pull Request 实现需求。为什么：任务步骤无法预判（要改哪些文件取决于需求本身），且有自动化测试可客观验证结果。怎么用：Agent 读代码 → 改文件 → 跑测试 → 看报错 → 再改，直到通过；Anthropic 自研编码智能体能仅凭 PR 描述解决 SWE-bench 真实 GitHub 问题，Claude Code 已被大量工程师日常使用。工具接口（ACI）与提示词的设计质量，往往比模型本身更决定成败。

3.2 客户服务：企业客服智能体

何时用：对话式交互 + 需要调取订单/知识库/执行退款等操作的客服场景。为什么：客服天然是"对话+动作"混合体，且有"解决率"可量化考核。怎么用：Agent 拉取客户信息 → 查订单 → 必要时执行退款/更新工单 → 按成功解决率付费；Anthropic 披露的 Coinbase 案例中，其客服 Agent 每小时处理数千条消息并保持高可用。传统聊天机器人到智能客服的区别，正是"只能聊"与"聊完能办事"。

3.3 通用多步任务与浏览器操作

何时用：跨网站/跨应用的一次性复杂任务——研究比较、填表、订票、资料整理。为什么：步骤多且高度不确定，固定脚本无法覆盖。怎么用：用户给一句话目标，Agent 操作浏览器/应用逐页完成（例如 OpenAI Operator、Manus 等产品方向；国内手机厂商"跨应用 Agent"可凭一句话完成续费查询取消等操作，荣耀、智谱 AutoGLM 等为公开案例）。此领域仍在快速发展，效果、成本与安全性依实现差异很大——演示效果普遍好于不受控的真实表现。

4边界辨析

4.1 相近概念对比

概念相同点关键区别典型形态
普通 LLM 对话 / Chatbot都用 LLM 生成文本一次生成即结束；无工具、无状态、无自主循环ChatGPT 基础问答
Function Calling 应用模型会调用工具单步"意图→一次函数调用"，流程由外部代码决定；Agent 是多步自主循环语音助手查天气
Workflow（工作流）同为 LLM+工具的智能系统代码预定义路径、可预测；Agent 由模型在运行时动态决定流程固定流水线：摘要→翻译→成稿
Agent—目标驱动、自主"思考→行动→观察"循环、可调工具与记忆、可纠错编码 Agent、客服 Agent

4.2 适用边界与失效条件

  • 前提假设：任务的目标可被清晰表达或可逐步澄清；存在可供调用的工具/接口；能获得执行反馈来验证进度。
  • 失效情形：一步就能完成的任务（杀鸡用牛刀，成本和延迟不值）；缺乏可靠工具或反馈信号的任务；高风险、不可逆操作若无人工审批环节则不适合全自主执行。
  • 已知局限：受上下文窗口限制（见《大模型的上下文》资料）；长期规划容易在遇到意外错误时跑偏；错误会随步骤累积放大；自然语言接口输出偶有格式错误。学界与厂商均提醒：Agent 的表现高度依赖外层脚手架（工具定义、权限、终止条件），一项结果不能简单归因为"模型多聪明"。

4.3 常见误区

  1. 误区：能调工具就是 Agent。纠正：单次 Function Calling 只是"工具化调用"，Agent 的关键是模型在循环里自主决定何时调用、调用什么、如何根据结果调整——缺少自主循环就不算。
  2. 误区：Agent = 更聪明的模型 / 通向 AGI 的捷径。纠正：Agent 是"模型+脚手架"的工程系统；自主性由部署配置决定，不是通用智能的标签。"会自主做事"不等于"理解正确"，价值对齐与安全护栏仍是开放问题。
  3. 误区：全自主最好，监督越少越先进。纠正：主流工程建议分级授权（关键动作人工批准），自主度应与风险匹配；"自主到什么程度"要明确说明（能做什么、不能做什么、何时交还人类）。

诚实边界：本领域演进极快（2024–2026 涌现大量产品与框架），"Agent 尚无统一标准定义"，不同厂商对 workflow/agent 的划界也有措辞差异。本资料以多来源共识为准，具体产品能力请以各厂商最新官方文档为准。
