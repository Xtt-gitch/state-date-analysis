CONCEPT LEARNING MATERIAL

Skill（智能体技能 / Agent Skill）

把"怎么做好某类任务"的专业知识打包成文件夹（SKILL.md + 可选脚本/资料），让通用 AI 助手的专业技能按需加载——学会一次，随处复用。

学科：人工智能 · 智能体工程 / 提示工程 难度：入门 → 进阶 别名：Agent Skill / 技能 / Skills（Anthropic Agent Skills 体系） 检索核实：2026-09-08

1个人解释

给"上一课的自己"讲：如果你每天要教一位聪明的实习生做十几件专业活，你不会把每件活的《操作规程》都贴满他的工位——你会把每份 SOP 装进各自的文件夹、写上封面简介（"这是什么、什么时候用"），让他先记住有哪些文件夹，等接到对应任务时再去翻对应的那本。Skill 之于 AI 助手，就是这些文件夹。

本质：Skill 是一个以文件系统形式存在的目录：必须包含一个带 YAML 元数据（name + description）的 SKILL.md，可选携带可执行脚本（scripts/）、参考文档（references/）、模板资源（assets/）。元数据里的 description 是"触发开关"——AI 靠它判断"这个任务要不要打开这份技能"。

为什么会出现：把大量一次性指令堆在系统提示词里会稀释模型注意力、浪费上下文；而 Skill 用"渐进式披露"解决：平时只占用每份技能约 100 token 的元数据，真正需要时才把完整指令读入。相比传统 Prompt，它可复用、可组合、可跨产品移植，还能附带确定性脚本（如用 Python 处理 Excel），把"生成式推理"和"确定性计算"结合。

生活化类比：提示词 = 随口交代的一句嘱托；Skill = 放在抽屉里、按需取阅的《岗位操作手册》。两者可以都做，但手册能让任何一位"员工"（不同会话、不同产品的 AI）都按同一标准办事。

2核心机制

2.1 标准目录结构

my-skill/                     技能根目录（文件夹名 = 技能标识）
├── SKILL.md                  必填：YAML 元数据 + Markdown 指令（"说明书"）
│     ├── name: my-skill      必填，小写字母+数字+连字符，与目录名一致（约 ≤64 字符）
│     └── description: …      必填，写明"做什么 + 何时用"，是触发匹配的依据（≤1024 字符）
├── scripts/                  可选：可执行脚本（Python/Bash…），确定性操作
├── references/               可选：参考文档，需要时按需读入上下文
└── assets/                   可选：模板/字体等，直接用于产出、不必读入上下文

2.2 三层加载：渐进式披露（Progressive Disclosure）

层级加载时机上下文开销内容
第 1 层：元数据启动即常驻每技能约 100 tokenname 与 description——AI 借此"知道有哪些技能、何时该用"
第 2 层：指令任务命中 description 时触发SKILL.md 主体（一般 <5k token）读入完整操作流程与最佳实践
第 3 层：资源与代码执行中按需读取前为 0references 按需读入；scripts 直接执行，只有输出回传上下文

正因为"未触发前只占元数据"，你可以安装很多技能而几乎不挤占上下文；也正因为脚本只回传输出，打包再多代码也不会把上下文塞满。

2.3 运行流程

启动：系统提示词里注入所有可用技能的 名称+描述（仅此而已）
   │
   ▼
用户请求到来：AI 比对各技能 description 是否与任务相关
   │
   ├─ 不相关 → 忽略该技能，正常处理（技能不消耗上下文）
   │
   ▼
相关 → 触发激活：读取该技能目录下的 SKILL.md 全文

   ▼

   │
   ▼
多个技能可组合（composable），AI 自动协调它们共同完成任务

2.4 生态与标准现状

  • 官方预置技能：Anthropic 提供 PowerPoint（pptx）、Excel（xlsx）、Word（docx）、PDF 等文档类 Agent Skills，可通过 API 的 skills 参数、Claude Code、claude.ai 等使用。
  • 自定义技能：把领域知识与组织流程打包为 SKILL.md 目录即可，个人/组织均可创建；团队与企业版支持组织级集中管理与扫描。
  • 开放标准：Anthropic 于 2025 年将 Agent Skills 作为开放标准发布在 agentskills.io，同一格式可跨采用该标准的平台使用。
  • 触发方式：大多数产品里由 AI 按 description 自动判断是否激活，无需用户手动选择——description 写得准不准，直接决定技能会不会被正确唤醒。

3应用场景

3.1 文档办公：PPT / Excel / Word / PDF 处理

何时用：用户要求"生成一份演示文稿/表格/合同"。为什么：文档格式细节繁杂，靠提示词临场发挥易错；技能可内置可靠的代码库。怎么用：触发技能后按 SKILL.md 流程执行——官方文档技能在 claude.ai 与 API 中已默认可用（quickstart 演示 10 分钟内用 pptx 技能生成演示文稿）；这也是许多人第一次"无感"用到技能的场景。

3.2 组织知识捕获：品牌规范 / 流程 / 机构知识

何时用：公司希望 AI 按统一规范产出——品牌配色版式、代码风格、合规流程、发布检查单。为什么：把"团队怎么做"沉淀成可版本管理的文件夹，全员、全项目一致执行，不必每次重述。怎么用：将工作流与最佳实践写进 SKILL.md（可含模板与校验脚本），组织统一发布；AI 在相关任务自动采用，等于给团队配了"永不忘记的老员工"。

3.3 个人学习工作流：把重复流程"技能化"

何时用：你反复要求 AI 按固定结构做某类事（如生成概念学习讲义、周报、调研笔记）。为什么：把"个人方法"固化成技能后，任何会话都能一键复现，还能迭代改进。怎么用：以"概念学习资料生成"为例——它就是一个典型 Skill：SKILL.md 规定输入、五段输出结构与自检清单；触发词是"帮我学透/生成学习资料"。这份学习资料的产出方式，本身就是该技能的应用实例。

3.4 数据分析等专业流水线

何时用：需要多步骤、带领域判断的分析任务（如客户流失分析：校验列→算留存指标→分群→出报告）。为什么：此类任务属于"Know-how"（怎么做），而非单次工具调用（Do-this），技能可编排多个工具并内置领域判断。怎么用：把流程、判定规则与输出模板打包；AI 只在收到该类请求时加载，避免无关任务互相干扰。

4边界辨析

4.1 相近概念对比（Skill vs 其他机制）

机制定位关键区别
Prompt / 自定义指令一次性或全局的对话级指示指令常驻所有对话、面向全局；Skill 面向特定任务、按需加载，更省上下文、更易专业化
工具 / Function / MCP"能调用什么"——外部连接与动作工具=执行能力（查天气、读数据库）；Skill=程序性知识（如何完成工作流、如何用好这些工具）。两者互补可并用：MCP 给连接，Skill 教方法
Project / 项目知识启动即常驻的静态背景知识Project 永远在上下文中；Skill 动态激活，跨产品通用，更适合专业流程
Skill 本身可复用的"Know-how 能力包"目录+元数据+渐进式披露；可组合、可移植、可版本管理

4.2 适用边界与失效条件

  • 适合做成 Skill：步骤可文档化的专业流程、可复用且频率高的任务、需要捆绑代码/模板/参考资料的任务。
  • 不适合：需要实时双向通信或访问专有外部系统的场景，通常更适合 MCP/工具连接而非静态技能；一次性随口问答也不必做成技能。
  • 失效条件：description 写得模糊 → 该触发时不触发、不该触发时误触发；环境不允许执行脚本 → 技能携带的代码能力失效（如 API 沙箱限制）。
  • 安全边界：技能通过指令与代码赋予 AI 新能力，恶意技能可能诱导不当工具调用或数据泄露——仅信任可信来源（自己创建或官方渠道），导入前审查 SKILL.md 与全部打包文件。

4.3 常见误区

  1. 误区：Skill = 工具函数。纠正：工具是"一步动作"（Do-this），Skill 是"一套做法"（Know-how：编排、校验、判断规则、输出标准），可内部调用多个工具。
  2. 误区：技能会常驻上下文、装多了变慢。纠正：平时只载入 name+description 元数据（约 100 token/个）；装几十个技能也不会明显挤占窗口。
  3. 误区：触发靠"技能名"被用户提到。纠正：现代实现中 AI 依据 description 与任务的语义匹配自动激活，用户往往无需手动点名——因此 description 质量决定技能生死。
  4. 误区：Skill 与 MCP 是对手、二选一。纠正：官方定位是互补（MCP 管连接、Skill 管方法，可同时使用）；部分工程文章认为 Skills 更轻量、正成为主流载体——存在观点分歧，选择取决于场景。

诚实边界："Skill"尚无统一的行业标准格式——Anthropic 主导的 Agent Skills 正被推动为开放标准（agentskills.io），但不同框架仍各有实现（YAML 清单、Python 模块、JSON schema 等）；各家对"技能/工具/插件"的命名与划分也存在措辞差异。本资料以 Anthropic Agent Skills 官方体系为主线呈现，兼顾多来源视角。
